🔄 Workflow 1 — เติมเงิน (Top-up)

  1. Staff รับเงินสดหรือยืนยัน QR แล้วเลือกลูกค้าในระบบ
  2. ตรวจสอบจำนวน: ขั้นต่ำ 20 บาท, สูงสุดต่อครั้ง 10,000 บาท
  3. อัปเดต users.balance += จำนวนที่เติม
  4. บันทึก wallet_transactions: type = topup, ref_type = cash_topup หรือ qr_topup
  5. ทุกขั้นตอนอยู่ใน DB::transaction() — ล้มเหลวตรงไหน Rollback ทั้งหมด

📦 Workflow 2 — ซื้อแพ็กเกจ (Buy Package)

  1. ลูกค้าเลือกแพ็กเกจจากหน้าเว็บ (ดึงจาก packages)
  2. ตรวจสอบ users.balance >= packages.price
  3. หักเงิน: users.balance -= price
  4. สร้าง record ใน user_packages: remaining_minutes = duration_hours × 60
  5. บันทึก wallet_transactions: type = deduct, ref_type = package_purchase

🖥️ Workflow 3 — เปิดเครื่อง (Open Session)

  1. เลือกเครื่องจาก Seat Map — ดึง seats ที่ status = available
  2. เลือกโหมด: A) Pay As You Go (ต้องมี balance ≥ 20 บาท) หรือ B) ใช้แพ็กเกจ
  3. สร้าง seat_sessions: status = active, start_time = now(), rate_snapshot = คัดลอกจาก zones.hourly_rate ทันที ⚡
  4. อัปเดต seats.status = occupied
  5. ถ้าใช้แพ็กเกจ: เชื่อม seat_sessions.user_package_id กับ user_packages

🍜 Workflow 4 — สั่งอาหาร (Place Order)

  1. ลูกค้าเลือกเมนูจากหน้า Order (ดึง products + categories)
  2. ตรวจสอบ products.stock_quantity เพียงพอ
  3. ตรวจสอบ users.balance >= ยอดรวม
  4. หักเงิน users.balance และตัดสต็อก products.stock_quantity
  5. สร้าง orders: payment_status = paid, order_status = pending
  6. สร้าง order_items: unit_price = คัดลอกราคาสินค้า ณ เวลานี้ ⚡
  7. บันทึก wallet_transactions: type = deduct, ref_type = order

🚪 Workflow 5 — จบเซสชัน (End Session)

  1. Staff กด Check-out หรือระบบตัดอัตโนมัติ
  2. คำนวณเวลาที่ใช้: end_time - start_time (นาที)
  3. Pay As You Go: ค่าใช้จ่าย = (นาทีที่ใช้ / 60) × rate_snapshot → หัก users.balance → บันทึก wallet_transactions
  4. ใช้แพ็กเกจ: หัก user_packages.remaining_minutes -= นาทีที่ใช้, total_cost = 0
  5. อัปเดต seat_sessions: status = completed, end_time = now()
  6. อัปเดต seats.status = available

เหตุผลในการออกแบบ (Design Rationale)

⚡ 1. Snapshot Pattern — ป้องกันราคาเปลี่ยนย้อนหลัง

ปัญหา: หากร้านปรับราคาโซนหรือเมนูอาหาร ยอดบิลเก่าที่บันทึกไว้จะผิดพลาด

วิธีแก้: คัดลอกราคา ณ เวลาที่ทำรายการเก็บไว้ในคอลัมน์แยก:

  • seat_sessions.rate_snapshot — จาก zones.hourly_rate ตอนเปิดเครื่อง
  • order_items.unit_price — จาก products.price ตอนสั่งอาหาร

ผล: ประวัติทางการเงินทุกรายการถูกต้อง แม้ราคาปัจจุบันจะเปลี่ยนไปแล้ว

🔒 2. Foreign Key Constraints — ป้องกัน Orphan Records

รูปแบบใช้กับผลที่เกิดขึ้น
RESTRICTความสัมพันธ์ส่วนใหญ่ห้ามลบข้อมูลต้นทางที่มีลูกผูกอยู่ → ป้องกันสูญเสียประวัติการเงิน
CASCADEorders → order_itemsลบออเดอร์แล้วรายการย่อยลบตาม → ไม่มีเศษข้อมูลค้างอยู่

🏦 3. ACID Transaction — การันตีความสมบูรณ์

ทุกรายการที่แตะข้อมูลมากกว่า 1 ตารางถูกห่อด้วย DB::transaction()

  • Atomicity: สำเร็จทั้งหมด หรือ Rollback ทั้งหมด — ไม่มีสถานะค้างกลางทาง
  • Consistency: users.balance ต้องตรงกับผลรวมใน wallet_transactions เสมอ
  • Isolation: แต่ละรายการไม่รบกวนกัน
  • Durability: เมื่อ commit แล้วข้อมูลบันทึกถาวร

📊 4. Rich Pivot Table (user_packages) — ไม่ใช่ Pivot ธรรมดา

ปัญหา: Pivot Table ทั่วไปไม่สามารถบันทึก "เวลาที่เหลือ" หรือ "วันหมดอายุ" ต่อ Instance ได้ และซื้อซ้ำไม่ได้

วิธีแก้: user_packages มี id เป็นของตัวเอง เก็บ remaining_minutes และ expired_at แยกต่อแถว → ลูกค้าซื้อแพ็กเกจเดิมซ้ำได้ไม่จำกัด

👤 5. Single Table Inheritance สำหรับ Role

แทนที่จะแยกตาราง admin/staff/customer ออกจากกัน ระบบเก็บทุก role ในตาราง users เดียว โดยใช้คอลัมน์ role แยกสิทธิ์ผ่าน Laravel Middleware
